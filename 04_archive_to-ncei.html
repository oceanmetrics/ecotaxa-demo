Images, TSV, DwC-A, metadata, SHA-256 manifest, verified locally. No submission.

Status

The package layout below is a proposal to agree with NCEI and with Matt Biddle and Enrique Montes, who are already working on NCEI publication of EcoTaxa data (the SECOORA LOI also names FathomNet in that work). It is BagIt-style because a checksummed, self-describing bag survives any transport. Which route NCEI prefers (Send2NCEI for a one-off, ATRAC with a submission agreement for a recurring flow, or a FathomNet-mediated path) and which metadata profile the imaging pipeline requires are the first questions for them; nothing here is an NCEI decision, and nothing here submits.

What a submission would then look like (assumption, to agree)

  1. Copy the bag to the staging bucket (egress-free object storage; a public copy via NODD if NOAA wants one), under ecotaxa/{dataset_key}/{version}/.
  2. Send NCEI the bag’s location and bag-info.txt through the agreed route (S2N for a pilot; ATRAC with a submission agreement for the recurring flow). The ISO 19115-2 record NCEI needs would be generated from the same EML with NCEI’s template once the profile is agreed; data/metadata/dataset.json holds the ACDD-style attributes it would draw on.
  3. On accession, write the accession number and DOI back into the project’s EML, so the next DwC-A version cites the archived copy.
  4. A re-validation or a new cruise makes a new version; a submitted version is never edited.

Lessons learned (project 4, 2026-11-10)

  • Scale. Project 4’s bag is 10.05 GB, 967,734 images and 967,842 payload files; build, manifest and verify (ok) take 12 minutes on the mini. Two loops that were fine on eight objects were not: copying one image per call (now one vectorized file.copy), and ncei_verify() looking each manifest entry up by name inside a loop, which is quadratic and ran for over half an hour without finishing (now one vectorized comparison; a test covers missing, unlisted and changed files together).
  • Spotlight on macOS indexes every new image and competes for the CPU; data/.metadata_never_index (made by scripts/render_project.sh) keeps it off.
  • One image per object: exporting with with_images = "first" is what removed the duplicate second images of the Ifremer backup; an "all" export would bring them back into the bag.
  • Print counts and the first lines, never a million-line listing, into a rendered page.

## What a submission would then look like (assumption, to agree)

1. Copy the bag to the staging bucket (egress-free object storage; a public copy via NODD if NOAA wants one),
   under `ecotaxa/{dataset_key}/{version}/`.
2. Send NCEI the bag's location and `bag-info.txt` through the agreed route (S2N for a pilot; ATRAC with a
   submission agreement for the recurring flow). The ISO 19115-2 record NCEI needs would be generated from the
   same EML with NCEI's template once the profile is agreed; `data/metadata/dataset.json` holds the ACDD-style
   attributes it would draw on.
3. On accession, write the accession number and DOI back into the project's EML, so the next DwC-A version
   cites the archived copy.
4. A re-validation or a new cruise makes a **new version**; a submitted version is never edited.

## Lessons learned (project 4, 2026-11-10)

  looking each manifest entry up by name inside a loop, which is quadratic and ran for over half an hour

- **Spotlight** on macOS indexes every new image and competes for the CPU; `data/.metadata_never_index` (made
