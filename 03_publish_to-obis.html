03 Build and validate the Darwin Core Archive for OBIS

  • Show All Code
  • Hide All Code
  • View Source

Event core, Occurrence, eMoF, EML, meta.xml, zip, checks. No upload.

What this does

From the cached export (01) and the reviewed lookup (02): one Event per sample (a child event per acquisition when a sample has several), Occurrence rows for validated objects aggregated per event and taxon, an extended MeasurementOrFact with the instrument (NERC L22 URI from the node), the sample volume, the object count, the concentration where a volume exists and the mean equivalent spherical diameter as exported, then EML, meta.xml, a deterministic DwC-A zip with a manifest, and the checks.

The upload to the OBIS-USA IPT stays a deliberate manual act by the data owner. Nothing here talks to a portal.

acquisition when a sample has several), **Occurrence** rows for validated objects aggregated per event and
taxon, an **extended MeasurementOrFact** with the instrument (NERC L22 URI from the node), the sample volume,
